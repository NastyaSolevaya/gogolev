# Вариант 5. Котельная

Курсовой проект по ПМ.02: виртуальная система сбора и учёта данных на Arduino Uno.
Система контролирует температуру воды, давление и расстояние до воды в баке.
При давлении выше 4 бар включаются реле клапана и белый светодиод.
Показания и события передаются через текстовый лог в Node-RED
и сохраняются в базе данных SQLite.

## Входные данные

- Вариант — 5.
- Сценарий — котельная.
- Микроконтроллер — Arduino Uno.
- Датчик s1 — NTC, температура воды, диапазон 0–100 °C.
- Датчик s2 — POT, давление, диапазон 0–6 бар.
- Датчик s3 — HC-SR04 (US), расстояние до воды в баке, диапазон 2–400 см.
- Исполнительное устройство — реле управления клапаном.
- Светодиод — белый, заданный ток 15 мА.
- Резистор светодиода — 120 Ом.
- Период измерений — 1 секунда.
- Условие включения реле и светодиода — давление выше 4 бар.
- Условие выключения — давление не выше 4 бар.

Аналоговые показания преобразуются по учебной линейной шкале
из задания: значение = мин + (макс − мин) × analogRead / 1023.
Давление выражается в барах, расстояние — в сантиметрах.
Чем меньше расстояние до воды (s3), тем выше уровень в баке.

## Порядок запуска

1. Убедиться, что Node.js, Node-RED и SQLite установлены,
   а команда sqlite3 доступна в окружении запуска Node-RED
   (её добавляет в PATH файл start-nodered.bat).
2. Запустить start-nodered.bat из папки проекта.
3. Открыть http://localhost:1880.
4. Если поток ещё не настроен, импортировать nodered/flow.json
   через меню → Импорт.
5. Проверить пути к файлам. Для относительных путей Node-RED
   должен быть запущен из папки проекта. Если в потоке сохранены
   абсолютные пути другого компьютера, заменить их.
6. Нажать «Развернуть» (Deploy).
7. Открыть проект Wokwi по ссылке выше и запустить симуляцию.
8. Скопировать строки DATA и EVENT из Serial Monitor,
   заменить ими содержимое data/log.txt и сохранить файл.
   Узел watch запустит загрузку автоматически.
   Для ручной загрузки нажать кнопку у узла inject («Загрузить вручную»).
9. Проверить отладочные сообщения: узлы sqlite stdout и sqlite stderr
   должны получить пустые строки, команда exec — завершиться с кодом 0.
10. В консоли из папки проекта выполнить:
    sqlite3 -header -column db/variant.db ".read db/queries.sql"

При каждой загрузке содержимое таблиц заменяется данными
из всего текущего лога. Это не накопление истории разных файлов.
Если db/load.sql уже сформирован, но выполнение команды
через Node-RED не сработало, загрузить его вручную:
sqlite3 -bail db/variant.db ".read db/schema.sql" ".read db/load.sql"

## Формат данных и событий

Пример строки измерения:
DATA n=1 s1=45.20 s2=3.40 s3=85.00

- n — номер измерения;
- s1 — температура воды, °C;
- s2 — давление, бар;
- s3 — расстояние до воды в баке, см.

При переходе в состояние тревоги (давление > 4 бар) скетч выводит
EVENT с типом THRESHOLD, при возврате в норму — NORMAL.
Событие выводится один раз при изменении состояния.
Node-RED формирует FAULT, если значение датчика
выходит за допустимый диапазон: s1 — 0…100 °C, s2 — 0…6 бар, s3 — 2…400 см.

## Проверка неисправности

В data/log_fault.txt используется строка:
DATA n=1 s1=50.0 s2=7.20 s3=60.0

1. Временно указать data/log_fault.txt в узлах watch и чтения файла.
2. Нажать «Развернуть» и запустить загрузку кнопкой у узла inject.
3. Проверить событие запросом:
   sqlite3 -header -column db/variant.db "SELECT * FROM events WHERE type='FAULT';"
4. Ожидаемый результат: событие FAULT с сообщением
   «датчик s2 вне диапазона» (давление 7.2 бар выше допустимых 6 бар).
5. После проверки вернуть в узлах путь data/log.txt,
   нажать «Развернуть» и загрузить обычный лог.

Тестовая запись FAULT при этом будет удалена из базы;
результат проверки сохраняется на скриншоте docs/fault-test.png.
